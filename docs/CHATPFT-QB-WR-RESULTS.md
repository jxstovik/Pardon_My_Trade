Ensemble: 50 bootstrap ridge models plus empirical residual variance

## Important Data Qualification

The repository does not yet contain a licensed, multi-season player-week
historical data set aligned to Razzball. The current run uses a deterministic
benchmark fixture generated by the training script. Its purpose is to verify
the complete modeling pipeline, artifact schema, probabilistic output, plots,
and benchmark calculations. These numbers must not be interpreted as NFL
forecasting performance.

Replace `generate_rows()` with licensed historical rows and rerun the exact
command before using the results for fantasy decisions.

## Validation Results

Metrics are calculated on player-week rows held out by season. Razzball is
compared as a point-prediction benchmark. Since the fixture does not provide a
Razzball uncertainty distribution, interval coverage is reported only for the
metamodel.

## Interpretation

On the benchmark fixture, the metamodel beats the Razzball point benchmark on
MAE and RMSE for both positions in the held-out season. The improvement is an
expected property of the generated fixture because its target was constructed
from related features. It is evidence that the pipeline can recover known
relationships, not evidence that the same advantage exists on real NFL data.

The validation P10-P90 coverage is approximately 76% for both positions. A
nominal 80% interval is slightly under-covered, so the next real-data step
should calibrate residual variance rather than claim calibrated uncertainty.

The near-zero validation bias is preferable to a high point score with a
systematic directional error. The Razzball WR positive bias in this fixture is
also fixture-specific and should be recomputed from real aligned rows.

## Output Artifacts

Each position directory contains:

- `model.json`: coefficients, features, ensemble size, and model version
- `metrics.json`: training and validation metrics
- `training_predictions.json`: training distributions
- `validation_predictions.json`: held-out distributions
- `<position>-metamodel.sqlite`: metamodel database
- `training-benchmark.svg`: training RMSE comparison
- `validation-benchmark.svg`: validation RMSE comparison
- `training-fit.svg`: actual versus predicted training output
- `validation-fit.svg`: actual versus predicted validation output

Databases contain:

- `metadata`
- `predictions`
- `metrics`
- `coefficients`

Example inspection:

```bash
sqlite3 artifacts/qb-wr-models/qb/qb-metamodel.sqlite \
  'select split, model, mae, rmse, p10_p90_coverage from metrics;'
```

## Replacing The Benchmark With Real Data

1. Obtain historical fantasy outcomes and projection snapshots with appropriate licenses.
2. Align player IDs and scoring periods before training.
3. Store Razzball projections taken before each scoring period.
4. Modify the training data loader while preserving feature cutoff rules.
5. Run the script and inspect validation metrics and fit images.
6. Compare against Razzball, ESPN, FFToday, and a position-only baseline.
7. Reject the model if validation error improves but interval coverage materially worsens.
8. Record the source date, data version, model version, and training cutoff.
